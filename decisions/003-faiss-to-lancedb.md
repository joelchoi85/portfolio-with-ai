# 003. FAISS → LanceDB (증분 색인)

RFP RAG System · 2026-09-02 ~ 03 · 커밋 `7166104`, `d5735d7`, `04ba4e4`

## 맥락

나라장터 공고는 매일 늘고, 정정공고로 내용이 바뀌고, 마감되면 빠진다. FAISS 인덱스는 부분 삭제와 메타데이터 필터가 안 돼서, 하나만 바뀌어도 전체를 다시 임베딩했다.

## 선택지

1. FAISS 유지, 매번 전체 재임베딩
2. FAISS 에 별도 ID 매핑을 붙여 삭제 흉내
3. 삭제·필터를 지원하는 저장소로 교체

## 결정

LanceDB. 두 저장소를 `STORE` 설정 하나로 바꿀 수 있게 두고 비교한 뒤 기본값을 LanceDB 로 바꿨다.

## 구현

- 청크마다 `doc_id + 본문 + 메타데이터` 해시를 남긴다
- 새 공고는 넣고, 해시가 바뀐 공고는 지웠다 다시 넣고, 목록에서 사라진 공고는 지운다
- 메타데이터를 해시에 넣은 건 버그 뒤였다. 본문이 같으면 제목이 새로 채워져도 그냥 지나갔다 (`ddef588`)
- 인덱스에 청크 지문과 임베딩 모델명을 남겨, 다른 전처리본이나 다른 모델로 만든 인덱스를 기동할 때 잡는다

## 결과

크론이 `prepare.py --build --service` 한 줄로 새 공고만 반영한다. 사람이 손대는 단계가 없어졌다.
